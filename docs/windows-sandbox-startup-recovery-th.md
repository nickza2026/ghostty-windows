# เปิดและปิด Sandbox ด้วยตัวเอง

คู่มือนี้สำหรับแพ็กที่อัปเดต launcher พร้อม `manager-recovery.cjs` แล้ว
ไฟล์ต้องอยู่ครบทั้งโฟลเดอร์ ไม่ใช่นำ `Sandbox.exe` ไปวางแยกตัวเดียว

## เปิด

เปิด `Sandbox.exe` ที่ root ของแพ็ก เช่น `A:\sandbox\Sandbox.exe`

- ถ้า VM เดิมยังทำงานและ manager ตอบด้วย identity ที่ตรงกัน จะเชื่อมเข้า VM เดิม
- ถ้า VM หยุดปกติ จะเริ่มด้วยดิสก์และบัญชีเดิม
- ถ้า manager ตายแล้วทิ้ง state ไว้ จะตรวจความเป็นเจ้าของ, process, ดิสก์,
  SSH port และทุก port-forward ก่อน ถ้าหลักฐานครบว่าไม่มีเจ้าของทำงานอยู่
  จะย้าย state เก่าไปเก็บใต้ `Data/recovery/<id>/manager.json` แล้วเริ่มใหม่
- การเปิดหลายครั้งใช้ lock ที่ Windows ปล่อยเมื่อ process ตาย ไม่อาศัยการลบ
  lock เก่าจากอายุไฟล์หรือ kill PID ที่บันทึกไว้

ไม่ต้องลบ `Data/manager.json` เอง และไม่ต้องเปลี่ยน SSH key หรือสร้างบัญชีใหม่
การกู้ไม่ได้ซ่อมหรือทิ้งดิสก์ที่เสีย และไม่ได้ตัดไฟให้ VM ที่ยังทำงานอยู่

ถ้าพิสูจน์ไม่ได้ว่าเริ่มใหม่ปลอดภัย โปรแกรมจะบอกข้อผิดพลาดและคงหน้าต่าง
terminal ไว้ให้อ่าน แทนการเปิด host shell หรือ reset ข้อมูลเพื่อให้ผ่าน
กดปุ่มเพื่อปิดหน้าต่างข้อผิดพลาด หรือปิดด้วย X ได้

## Copy/paste ข้อความ

ในรุ่นที่อัปเดต native clipboard shortcuts แล้ว:

- ลากเลือกข้อความ แล้วกด `Ctrl+C` เพื่อคัดลอก
- `Ctrl+V` วางข้อความ; `Ctrl+Shift+C/V` ยังใช้ได้
- เมื่อไม่มีข้อความที่เลือก `Ctrl+C` ยังส่ง interrupt ให้คำสั่งใน terminal
- การวางหลายบรรทัดมีหน้าต่างยืนยัน เพราะข้อความอาจเป็นคำสั่งที่ทำงานทันที

การอัปเดตไฟล์ EXE ไม่เปลี่ยนโค้ดในหน้าต่างที่เปิดค้างอยู่
เปิด `Sandbox.exe` เป็นหน้าต่างใหม่เพื่อใช้คีย์รุ่นใหม่ โดยไม่ต้องหยุด VM
ไม่มีการเปิด automatic guest-to-host clipboard sync หรือยกเลิก OSC52 filter

## ปิด

ปิดหน้าต่าง terminal ด้วย X หรือ `exit` เป็นการตัด terminal session เท่านั้น
ส่วน VM และ guest services ยังอยู่

ถ้าจะหยุด VM ทั้งตัว ให้บันทึกงานแล้วเปิด `Stop-Sandbox.cmd`
รอให้หยุดเรียบร้อย และให้ Windows ทำ Safely Remove Hardware สำเร็จก่อนถอดไดรฟ์
ถ้า Windows ยังแจ้งว่าถูกใช้งานอยู่ อย่าฝืนถอด
อย่าใช้ `Force-Stop-Sandbox.cmd` เป็นวิธีปิดปกติ

## Herdr และ Web

ใน guest ที่ติดตั้ง user services ไว้แล้ว บริการจะเริ่มตาม user manager
เมื่อ VM เปิด ไม่ต้องมีหน้าต่าง Herdr/Web ค้างอยู่ หน้าเว็บบน Windows คือ
`http://127.0.0.1:18787` และ AI auto-resume ของ native service ปิดอยู่

รายละเอียดการจัดการเฉพาะบริการอยู่ใน
[คู่มือ guest services](windows-herdr-guest-services-th.md)

## ขอบเขตความปลอดภัย

state ผิดรูปแบบ, package identity ไม่ตรง, symlink/hardlink ที่ไม่รองรับ,
process ที่ยังอยู่หรือระบุตัวไม่ได้, ดิสก์ที่ยังมีคนเปิด, และพอร์ตที่ยังมี
listener หรือให้ผลคลุมเครือ จะไม่ถูกตีความว่าเริ่มทับได้

บน exFAT ยังเป็น reduced-protection ตามที่ยอมรับไว้: ผู้ที่เข้าถึงไดรฟ์
สามารถอ่านหรือแก้ข้อมูลและ keys ได้ ระบบกู้ state ไม่ได้เพิ่ม NTFS ACL ให้ exFAT
และไม่เปลี่ยนบริการ Windows, firewall, Tailscale หรือบัญชีเครื่องให้เอง
